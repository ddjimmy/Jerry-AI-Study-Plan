# Study Rules

[中文版本](STUDY-RULES.zh-CN.md)

## Weekly Rhythm

- Monday–Friday: 60–90 minutes per day.
- Saturday: 30–45 minute demo and review.
- Sunday: rest or optional exploration.
- Aim for about 30% learning and 70% building.

## Daily Session

1. 10 min — Review yesterday's code.
2. 20 min — Learn one concept.
3. 40–50 min — Build or debug.
4. 10 min — Commit code and write learning notes.
5. 5 min — Define tomorrow's next step.

## Output Over Screen Time

A study session counts when it produces something concrete:

- code,
- a working experiment,
- a chart,
- a model result,
- a Git commit,
- a short technical note,
- or a demo.

Simply watching videos does not count as the main work.

## Explain-or-It-Doesn't-Count Rule

AI tools may be used for:

- explanations,
- hints,
- debugging,
- code review,
- architecture suggestions,
- small examples.

AI tools should not be used to blindly generate an entire assignment or project.

If the student cannot explain an important section of AI-generated code, that section is not considered completed.

## Entertainment Rule

Gaming, Discord/chatting, Shorts/TikTok, casual YouTube, and browser mini-games are treated as entertainment time.

Daily AI work should be completed before entertainment time.

## Bilingual Documentation Rule

- English is the primary language for code, Git commits, and portfolio presentation.
- Important learning materials must have complete English and Simplified Chinese versions.
- When one language version changes materially, update and verify its counterpart.
- Every document pair must include working cross-language links near the top.
- Executable source code is shared; do not create separate implementations by language.
